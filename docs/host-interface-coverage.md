# Host interface coverage

Audited on 2026-11-01 against the pinned App UI **26.1013.40934** and the
experimental protocol schema generated by Codex CLI **0.164.0**. Yard serves the
original interface, whose controls can call host services that Yard has not
implemented. A visible control therefore needs its host contract checked.

The audit examined literal `sendRequest` call sites, adjacent request helpers,
the Web RPC allowlist, browser host services, and the running host's rejected
requests. Protocol method catalogs were used to identify interfaces; a catalog
entry alone was not treated as evidence that a UI control calls it. Conditional
and dynamically constructed calls still require validation of their entry point.

## Connected in this change

| User action | Native methods added to the existing bridge |
| --- | --- |
| Compact an idle conversation with `/compact` | `thread/compact/start` |
| Search conversations and locate matching messages | `thread/search`, `thread/searchOccurrences` |
| Read the native conversation timeline | `thread/timeline/list` |
| Find files, including the composer's file search session | `fuzzyFileSearch`, `fuzzyFileSearch/sessionStart`, `fuzzyFileSearch/sessionUpdate`, `fuzzyFileSearch/sessionStop` |
| Enable or disable an existing Skill | `skills/config/write` |
| Write a configuration value and reload MCP servers | `config/value/write`, `config/mcpServer/reload` |
| Clean background terminals, change conversation memory mode or metadata, and update active-turn settings | `thread/backgroundTerminals/clean`, `thread/memoryMode/set`, `thread/metadata/update`, `turn/settings/update` |
| Read account limits and app details or installed app status | `account/rateLimits/read`, `app/read`, `app/installed` |

All 18 methods use the existing selected-host connection. Native response
schemas, pagination, error codes/data, and progress notifications pass through
unchanged. `null` and omitted RPC parameters retain their wire representation;
CLI 0.164.0 also accepts an empty object for MCP reload. Writes and file-search
session changes report an uncertain result after a lost reply; the bridge does
not replay them. Configuration reads continue to redact credentials and
provider/MCP environment values.

`thread/compact/start` acknowledges immediately; completion is reported through
normal item/turn notifications, including a `contextCompaction` item. The pinned
UI disables manual compaction while a response is running. See the
[official App Server protocol](https://learn.chatgpt.com/docs/app-server).

## Standalone plugins and desktop control

On 2026-11-08, the existing selected-host bridge also connected marketplace
addition/removal/upgrade, plugin search/install/uninstall/reconciliation/sharing,
plugin Skill reads, and MCP OAuth/resource/tool/event operations. Native
responses, errors and notifications pass through unchanged; lost write replies
are never replayed. OAuth callback reachability depends on the backend host and
the service's configuration. The repository-owned `yard-computer` MCP runtime
provides Linux X11 desktop control without Codex App. Setup and environment
boundaries are described in [standalone plugins](standalone-plugins.md).

## Remaining interfaces

As of 2026-11-06, the original Scheduled page uses Yard-owned task storage and
the persistent Node scheduler. `list-automations`, `automation-create/update/delete`,
`automation-run-now`, `inbox-items`, read-state and archive operations are implemented.
The service creates conversations through existing local/SSH Codex connections,
without a running desktop App or browser. See [scheduling and recovery](scheduled-tasks.md)
for supported task types and validation.

These are confirmed gaps in the pinned renderer's host integration. Some
controls depend on capabilities, account type, platform, or feature flags and
may not appear in every session. They remain outside this change.

| Affected capability | Missing contracts and consequence |
| --- | --- |
| Attachment staging and file change notifications | `fs/copy`, `fs/remove`, `fs/watch`, `fs/unwatch`. Browser upload, download and previews use Yard's existing file services; native staging cleanup and live file watchers need their own ownership/lifecycle integration. |
| Login, logout and provider enrollment | `account/login/start`, `account/login/cancel`, `account/logout`, `account/gatewayOAuth/login`, `account/gatewayOAuth/cancel`, `account/bedrock/discover`, `account/bedrock/setup`. Yard currently uses an already configured CLI account. |
| Resetting rate limits with credits | `account/rateLimitResetCredit/consume` appears in the usage execution helper. Reading limits is connected; consuming credits is not. |
| Memory management | `memory/status`, `memory/reset`. The per-conversation memory toggle is connected; global memory inspection/reset is not. |
| Remote control pairing and clients | Pairing, client list/revocation, and the conditional `remoteControl/enable` / `remoteControl/disable` calls are not connected. Yard's SSH connections have a separate existing transport and catalog. |
| Realtime voice sessions | `thread/realtime/start`, `thread/realtime/stop`, `thread/realtime/appendText`, `thread/realtime/appendSpeech`, plus desktop microphone/global-hotkey services. |
| Managed worktrees and native projects | `thread/attachment/add`, `thread/attachment/remove`, `thread/attachmentOwner/list`, `project/list`, `command/exec`, Git worker requests, and the managed-worktree host service. Yard's project navigation and terminal use existing separate services. Archive already has an adapter for the absent worktree cleanup service. |
| Approving a Guardian-denied action | `thread/approveGuardianDeniedAction`. Ordinary backend approval request/response forwarding is already connected. |
| Windows sandbox setup | `windowsSandbox/readiness`, `windowsSandbox/setupStart`; the validated Yard server currently runs on Linux. |
| Diagnostic upload | `feedback/upload`, including its native log staging and consent flow. |

The running host also rejected these desktop fetch/worker contracts during the
audit: `worktree-shell-environment-config`, `git-origins`, `git/availability`,
`git/stable-metadata`, `ambient-suggestions`,
`global-dictation-hotkey-state`, `external-agent-import-status`, and
`local-custom-agents`. These affect worktree shell defaults, repository metadata,
suggestions, global dictation, external setup import and custom
agent discovery respectively. They require host implementations beyond an RPC
allowlist entry.

The renderer also contains `thread/stop` for durable conversations and
`gitDiffToRemote`. Neither appears in CLI 0.164.0's generated protocol. HTTP
verbs used by the renderer's unrelated network client are not Codex RPC methods.
`getAuthStatus` is a working legacy request and remains supported. Older allowed
names such as `thread/rollback`, `thread/readState/read`, `thread/readState/set`,
`thread/metadata/read`, and `thread/goal/update` were left unchanged; the selected
backend decides which legacy requests it supports. No aliases were invented
from similarly named newer interfaces.

## Validation

Portable integration tests cover selected local/SSH-host routing, native errors,
search cursors and match data, file-search notifications, null/omitted parameters,
and lost write replies without replay. Full-UI validation uses the pinned assets
and a disposable real CLI 0.164.0 with a local synthetic model provider. It does
not compact user conversations or modify the user's CLI configuration.

The original `/compact` menu is exercised through a browser click. Additional
search and settings requests are checked through that page's browser bridge.
Account-provider responses, actual remote servers, microphone permissions and
the remaining capabilities above require separate feature validation.
