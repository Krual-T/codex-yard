# Yard 独立定时任务

## 目标与执行边界

Codex App 未安装或未运行、所有网页已关闭时，Yard 的常驻 Node 服务仍按时创建并执行会话。用户在 Yard 配置任务、查看运行记录，再进入已有会话界面继续交流。运行依赖 Yard 服务、Codex CLI 执行后端及其正常认证；机器关机期间不能执行，恢复后合并漏跑。

Yard 在自己的 `AGENTS_DATA_DIR` 保存任务和运行记录。启动不读取 App 的 automation TOML 或 SQLite，也不自动接管其中的任务。复盘任务通过 Yard 的普通创建接口登记；启用同一任务前应暂停旧调度方，避免两个独立调度器各执行一次。

## 复用与实现位置

| 位置 | 职责和复用依据 |
| --- | --- |
| `src/native/server.ts` | 已有常驻生命周期、来源校验、Codex 连接、项目列表、会话归属和本机工具配置；新增任务服务生命周期及 API，提取现有项目列表和归属函数供两处复用。 |
| `lib/codex.ts` | 原样使用 `CodexConnection` 的请求、事件和不确定写入错误。调度执行复用 `thread/start`、`turn/start`、`thread/read`。 |
| `src/native/automations.ts` | 任务校验、SQLite 持久化、到期领取、执行与状态恢复；一个服务拥有上述流程，避免再分调度框架和执行插件。 |
| `src/native/automation-recurrence.ts` 及 worker | 使用 `rrule` 计算下一时刻。独立 worker 限制计算时间并固定 UTC 环境，任务保存 IANA 时区和固定 DTSTART，避免服务器时区、重启或编辑名称改变周期锚点。 |
| 原 Scheduled 页面、`src/native/automation-renderer.ts` | 保留固定页面的布局、路由和操作，补齐 `list-automations`、`automation-create/update/delete/run-now` 及 `inbox-items` 宿主接口。自有适配将新建默认设为原生 cron 表单，并以 Yard 的本地调度能力替代 App 账户能力判断；vendor 原件不修改。 |
| `src/native/browser-automation-recovery.ts` | 在原运行记录下显示异常说明及核查后的解除操作，共用原页面 React runtime；不新增管理页。资源前缀升至 `/web-renderer-v3`，使浏览器重新取得适配后的资源。 |

历史独立仓库 `react-ts-settings-sections` 分支的 automation-service/scheduler 主要处理 App 文件接管、账户归属、heartbeat、租约和云缓存。本次任务的数据归 Yard 所有，复用其 RRULE 独立计算思路；不引入这些无当前消费者的接管层。原 Scheduled 页面已有独立的本地任务分支，继续复用它。

## 用户操作与正常执行

1. 创建任务，保存名称、提示词、项目、RRULE、时区、可选模型与推理强度。在已有本机或 SSH 项目目录、或 Yard 的无项目工作目录中新建独立会话；工作树创建、heartbeat 和云任务留在原有边界之外。默认使用后端已配置的权限，不自动提升权限或回答审批。
2. 创建/修改成功表示任务已持久化。修改周期或时区时重新设置周期起点；修改提示词或名称保留原周期。暂停清除下次时间，重新启用从当前时间向后安排。删除停止后续触发，保留已有运行历史与会话。
3. 服务启动后立即检查，之后每 30 秒检查到期任务。每任务最多一个尚未结束的运行，全局最多三个。手动执行也使用同一领取逻辑，暂停任务可手动执行。
4. 连接后端和计算周期之后，重新核对任务版本、删除/启用状态、到期时间和并发占用；随后在同一个 SQLite 事务中插入运行、记录原到期时间、推进下次时间。领取提交是执行生效点，提交前的编辑使领取失效，提交后的编辑影响下次运行。手动执行不消费下次时间。
5. 使用领取时的定义创建会话，取得 ID 后立即保存，再设置项目归属、标题并发送提示词。所有写 RPC 标记 `mutating: true`；以已持久化的 `run.id` 作为 `clientUserMessageId`。执行不依赖浏览器连接。
6. 服务读取正在执行的会话并更新运行状态，网页只读取结果。完成记录保留会话入口；需要审批时保持会话执行状态，用户进入原会话后通过原有审批界面继续。

运行状态的异步回读只合并执行字段，保留等待期间用户修改的已读和归档状态。已完成、失败或人工解除的记录不被旧回复重新改为执行中。原页面通过 `description` 读取摘要及错误，通过既有会话入口继续交流；未取得会话 ID 的未知结果也有独立的核查解除入口。

## 数据与保证

`automations.sqlite` 包含任务和运行两张表。任务以 ID 为主键，保存定义、创建/更新时间及下次时间。运行保存 ID、任务 ID、实际 hostId、到期时间（手动运行为空）、状态、会话/turn ID、错误与时间。恢复直接使用运行的 hostId，不依赖已编辑或删除的任务。每个自动到期时间唯一；每个任务至多一条处于启动中、运行中、等待处理或待核实的记录，由唯一索引保证。运行列表按时间分页；默认只返回最近 100 条。

服务持有独立 SQLite 锁文件的排他事务，阻止同一数据目录被两个 Yard 调度器同时使用。操作系统在进程退出时释放锁，包括异常退出。这个文件仅负责进程所有权；任务库独立提交，已领取运行在崩溃后仍存在。启动先取得所有权，再创建服务工具 socket。

运行状态为 `starting → running / waiting → completed / failed`，以及 `uncertain`。后者表示请求可能已经产生副作用但无法证明结果，不自动重发。调度器对后台错误保留可见诊断，不吞掉失败。

## 中断和恢复

| 情况 | 行为 |
| --- | --- |
| 网页或 App 关闭 | 服务继续调度；重新打开 Yard 后读取同一记录。 |
| 服务关闭多天 | 每个已到期任务补跑一次，保留原到期时间，将下次时间推进到当前时刻之后，不按漏掉的天数批量启动。 |
| 同一任务仍运行 | 暂缓新的到期运行；结束后将漏掉的时刻合并为一次。 |
| 后端暂时不可连接 | 领取前连接失败保留到期时间，稍后检查；领取后失败保存 failed 或 uncertain，不静默重复写入。 |
| 已领取但尚无会话 ID 时崩溃 | 标为 uncertain，保留该次记录并阻止同任务再次自动启动。界面可确认已核查后结束此记录，之后再手动重跑。 |
| 已有会话 ID，发送 turn 结果丢失 | 按 turnId 跟踪；未取得 turnId 时分页查找用户消息的 `clientId === run.id`，恢复其轮次。用户发送的其他轮次不作为证据，查不到时保持 uncertain。 |
| 运行中重启 | 从保存的会话 ID 读取进度；不会再次创建会话或发送提示词。后端不再加载但记录仍 inProgress 时标为 uncertain。 |
| 用户解除 uncertain 记录 | 保留原始未知结果，以 released 状态表示停止跟踪，显示“结果未知，已解除”；仅解除调度阻塞，不中断已有会话。对仍运行的会话拒绝解除。 |
| 项目被移除或模型不可用 | 执行失败可见，不自行切换项目、模型或权限。 |

关闭 Yard 停止新领取，等当前启动操作结束后释放所有权，保留 Codex 后端中已开始的会话。完成状态通过会话历史中的 turn 状态确认；一次没有运行 turn 的空读取不能当作安全重试依据。

实际 CLI 0.164.0 的分页会话历史通过 `thread/turns/list` 读取。隔离验证已确认 `clientId` 持久保存；后台零网页触发的 command approval 在 Yard 重启后，由后来连接的 `thread/resume` 回放，并能通过原协议答复完成。因此复用原页面连接及审批回复路径，不增加审批代理。验证脚本为 `scripts/verify-automation-cli.ts`，使用本地 Responses 测试服务，没有个人账户或外部推理。
